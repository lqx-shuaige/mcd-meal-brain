## 2. 营养约束映射表（减脂）

**单餐（一顿）参考阈值**，按严格度分档。成年人每日参考 2000 kcal，午餐/晚餐按 25–30% 计。

| 档位 | 单餐热量上限 | 脂肪上限 | 蛋白下限 | 钠上限 | 适用 |
|---|---|---|---|---|---|
| 严格减脂 | **500 kcal** | **20 g** | 25 g | 800 mg | 明确"减脂/控卡" |
| 标准减脂 | **600 kcal** | **25 g** | 20 g | 1000 mg | "少吃点/清淡些" |
| 常规 | **750 kcal** | 30 g | 15 g | 1200 mg | 无特殊要求 |

**按人数换算团队上限**：`总热量上限 = 单餐上限 × 人数`（用于团队方案体检）。

### 2.1 达标组合示例（真实数据，可直接引用）

**① 严格减脂（444 kcal / 脂肪 18 g / 蛋白 25 g）**
```
板烧鸡腿堡        391 kcal  蛋白23  脂肪17
小杯玉米杯         53 kcal  蛋白 2  脂肪 1
无糖可口可乐中杯    0 kcal
────────────────────────────────
合计              444 kcal  蛋白25  脂肪18   ✅ 全部达标
```

**② 标准减脂（407 kcal / 脂肪 16 g / 蛋白 22 g）**
```
原味板烧鸡腿麦满分  246 kcal  蛋白15  脂肪 9
纯牛奶（盒装）     129 kcal  蛋白 7  脂肪 7
苹果片             32 kcal
────────────────────────────────
合计              407 kcal  蛋白22  脂肪16   ✅
```

**③ 反面教材（不达标）**
```
巨无霸 + 中薯条 + 可乐中杯 = 513+289+165 ≈ 967 kcal，脂肪 38 g
→ 超严格档热量 93%、脂肪 90%，**减脂场景必须淘汰**
```

> 组合公式：**1 主堡（低脂高蛋白）+ 1 蔬菜/玉米杯 + 1 零卡饮**
> 是实现"减脂达标 + 不饿"的最稳结构。

## 3. 多人偏好解析规则

### 3.1 从自然语言提取约束

| 语言信号 | 提取为 | 层级 |
|---|---|---|
| 不吃 / 不能吃 / 过敏 / 忌 / 禁忌 / 千万别 | 成分黑名单 | **硬** |
| 必须要 / 一定要 / 必须有 | 必点项 | **硬** |
| 预算 X / 人均 X / 不超过 X | 预算上限 | **硬** |
| 几个人 / 我们有 N 人 | 人数 | **硬**（上下文参数） |
| 喜欢 / 想 / 最好 / 倾向 / 偏爱 | 口味偏好 | 软 |
| 减脂 / 控卡 / 少吃油 / 健身 | 营养目标 | 软（可升级为硬，见 3.3） |
| 随便 / 都行 / 无所谓 | 不设约束 | — |

### 3.2 成分同义词归一（关键！避免漏判）

用户说"不吃牛"、"牛肉过敏"、"不碰牛排"必须命中同一黑名单项。归一表：

| 用户可能说法 | 标准标签 |
|---|---|
| 牛 / 牛肉 / 牛排 / 安格斯 / 牛堡 | `beef` |
| 猪 / 猪肉 / 培根 / 猪柳 / 火腿 / 香肠 | `pork` |
| 鸡 / 鸡肉 / 鸡腿 / 鸡翅 / 板烧 / 麦乐鸡 | `chicken` |
| 鱼 / 鳕鱼 / 麦香鱼 / 鱼排 | `fish` |
| 虾 / 海鲜 | `seafood` |
| 辣 / 辣的 / 麻辣 / 香辣 | `spicy` |
| 油炸 / 炸的 / 煎炸 | `fried` |
| 奶 / 牛奶 / 芝士 / 冰淇淋 / 奶铁 | `dairy` |
| 花生 / 坚果 | `peanut`（**过敏项，最高优先级**） |
| 冰 / 冷饮 | `iced` |

### 3.3 软约束升级为硬约束的触发条件

满足任一即升级（因为"偏好"变"需求"）：
- 出现过敏词（过敏/过敏原/吃了会出事）→ 无条件升级
- 出现"必须/一定/绝对不能"→ 升级
- 用户指明某人有健康状况（糖尿病/高血压/术后）→ 相关项升级
- 减脂者明确给出数字（"这顿 500 大卡以内"）→ 热量升级为硬上限

否则保持软约束，只参与打分。

### 3.4 解析输出

解析结果必须落到 `references/workflow.md` 第 4 节（多人偏好解析）的画像 JSON：
每人 `hard[] / soft{prefer,avoid} / targets{} / weight{}`，
团队级 `aggregated{hard_union, budget_ceiling_cny, must_have, conflicts}`。

## 4. 硬约束 vs 软约束处理逻辑

### 4.1 硬约束：一票否决 + 取并集

```
任一参与者忌口 → 全队候选集中剔除该成分
```
- 执行时机：**优化之前**（先缩小解空间，再谈最优）
- 实现：`scripts/optimizer.py::filter_menu()` 第一层过滤
- 记录：每个被剔除的商品都要能回答"为什么被剔除"（用于向用户解释）

**冲突优先级（从高到低，高优先不可被低优先推翻）：**

```
① 安全（过敏）  >  ② 信仰/忌口  >  ③ 预算上限  >  ④ 人数
>  ⑤ 营养目标  >  ⑥ 口味偏好  >  ⑦ 凑券/赠品
```

> 例：为凑"满 99 减 15"而想加点牛肉汉堡时，若有人不吃牛肉 → **立即否决凑单方案**，
> 换用其他方式凑单或直接放弃该优惠。

### 4.2 软约束：NSGA-II 多目标优化（默认）+ 加权评分（回退）

**NSGA-II 路径（`optimize_plans` 默认，批 2 算法升级）**——不再依赖主观权重：

四目标向量（**全部最小化**）：

| 目标 | 含义 | 来源字段 |
|---|---|---|
| `final_price_cny` | 券后最终价（越低越好） | `_basket_to_plan` + 券组合 DP |
| `per_capita_kcal` | 人均热量 | nutrition 表 |
| `fried_count` | 油炸份数（出餐速度代理） | 菜品标签 |
| `-per_capita_protein_g` | 负人均蛋白（越高越好） | nutrition 表 |

流程：初始种群（DP 最省钱解 + 成本-热量曲线抽样 + 贪心健康/快 + 随机个体）→
锦标赛选择 + 均匀交叉 + 变异 + 可行性修复（主食≥人数、热量≤上限、单位≤上限）→
**快速非支配排序 + 拥挤距离**环境选择，演化 20 代 × 40 个体（固定种子 20261010，可复现）→
最终用**券后价**重建方案并重新分层 → 第一前沿选「最省钱（min 价）/ 最健康（max 蛋白，
显式脂肪目标存在且有达标者时只在达标子集选）/ 最快（min 油炸）」命名极值，
并按前沿有效多样性**自适应补席**（v1.1.0 起，共 1–5 套，`top_n` 默认 5）：

- 极值撞篮时由**同目标值**并列者顶替标签，更差者不冒名；
- 补席按拥挤距离降序，须与已选方案「明显不同」（价差 ≥max(¥1, 5%) 或人均
  热量差 ≥75 kcal 或蛋白/脂肪差 ≥6 g），近重复解折叠；
- 补席与「最健康」同脂肪达标口径，不反超命名极值的标签语义；
- 前沿退化时输出 1–2 套即止（不凑数）；详见 `workflow.md` 第 6 步。

**加权评分路径（`method="weighted"`，保留作对照与回退）**：

```
Score = w_cheap   × S_cheap
      + w_healthy × S_healthy
      + w_speed   × S_speed
      + w_pref    × S_pref
      - P_violation
```

| 分项 | 计算 |
|---|---|
| `S_cheap` | `1 − 最终价 / 预算上限`（越省越高） |
| `S_healthy` | 按 targets 达标率：热量/脂肪达标 +1，蛋白达标 +1，归一化 |
| `S_speed` | 油炸/现制项越少越高（出餐快），或按预估出餐时间反比 |
| `S_pref` | 命中 `soft.prefer` 计数 − 命中 `soft.avoid` 计数 |
| `P_violation` | 软性惩罚（违反 avoid 但未违反 hard 时扣分） |

**权重来源**：取团队内各人 `weight` 的**加权平均**（按人数），
若某人立场极端（如预算控 `w_cheap=0.9`），允许其主导但需在输出中说明。

### 4.3 帕累托剪枝

保留"不被任何其他方案在所有目标上同时碾压"的解：
- 目标维度：`(最终价↑越低越好, 热量↓越低越好, 蛋白↑, 出餐速度↑)`
- 剪枝后按席位规则选代表解（命名极值 + 均衡补席，见 4.2），不再固定 Top-3

### 4.4 无解处理

若硬约束过滤后候选集为空（或无法满足人数/预算）：
1. **不静默放宽**任何硬约束；
2. 明确报告无解 + 列出冲突项（如"3 人忌牛、2 人忌辣，剩余可选仅 9 项，凑不齐 6 人份"）；
3. 给出可选放宽项让用户决策（"是否允许加一份牛肉堡单独给不吃忌口的人？"）。

**极端预算降级（方向 4 新增）**：
若预算不足以覆盖最低需求（连最便宜的主食都买不起）：
- 自动生成「减配方案」：贪心选择预算内最便宜的商品组合；
- 明确标注预算差距（如"距离预算差 Y 元，建议调整预算或减少人数"）；
- 绝不崩溃或输出无解，而是给出可操作的建议（增加预算 / 减少人数 / 分步下单）。

### 4.5 结果自检清单（输出前必过）

- [ ] 所有 `hard` 成分均已从候选中剔除？
- [ ] 价格已 ÷100 转「元」？
- [ ] 券来自 `query-store-coupons`（而非 `available-coupons`/`query-my-coupons`）？
- [ ] 人均是否超预算？
- [ ] 热量/脂肪是否满足减脂档位？
- [ ] 每个方案是否有明确取舍说明？
- [ ] 写操作是否已获用户确认？

## 5. 群体偏好聚合规则

> 实现：`scripts/optimizer.py::aggregate_preferences(members)` +
> `fairness_score(plan, aggregated)` + `optimize_group_plans(...)`。
> 成员输入支持自然语言字符串（自动解析 + 口味强度推断）或结构化 dict。

### 5.1 硬约束交集规则（一票否决）

「交集」指**每个人能吃集合的交集** = **全员禁忌并集的补集**：
A 不吃辣、B 不吃牛肉 → 菜单同时排除辣和牛肉。

- 禁忌并集**不可被多数推翻**（3 人里 1 人过敏，照样全队排除）；
- 与第 4.1 节冲突优先级一致：`安全(过敏) > 信仰/忌口 > …`；
- 预算聚合同样取最严：总额上限 = 各成员预算的最小值；
- 营养目标聚合：`max_*` 取最小、`min_*` 取最大（最严者胜）。

### 5.2 软约束自适应截尾均值

口味强度标尺 **0–5**（0 不辣 … 5 变态辣），成员可显式声明或从自然语言推断
（「无辣不欢」→5、「很辣」→4、「中辣」→3、「微辣」→2、「不吃辣/怕辣」→0）。

**算法**：某维度上收集所有表达过意见的成员强度 → 排序 → **两端各去掉
`n // 4` 个极端值（仅当 n ≥ 4；n < 4 不截尾）** → 取算术均值。

| 成员强度 | 截尾过程 | 结果 |
|---|---|---|
| 很辣4 / 中辣2 / 不辣0 / 不辣0 | 去掉 4 和一个 0 → [0, 2] | **1.0**（微辣以下） |
| 不辣0 / 变态辣5（n=2） | 不截尾 | 2.5（但触发冲突检测，见 5.3） |

软偏好的其他维度：`prefer_tags` 取**多数**（≥半数成员提到才进聚合偏好），
`avoid_tags` 取**并集**（更保守：任何人的软性不喜欢都计入扣分项）。

### 5.3 严重冲突判定标准

某口味维度上把表达过意见的成员分为两阵营：**强度 ≥ 3（要辣组）** vs **强度 ≤ 1
（不要辣组）**。同时满足以下两条即判「严重对立、无法用截尾均值调和」：

1. 两个阵营人数均 ≥ **⌈投票人数 / 3⌉**（双方都有实质代表性）；
2. 两阵营均值差 ≥ **3**（口味鸿沟足够大）。

判为冲突 → 标记 `needs_negotiation`，输出 **A/B 两套备选**：

| 备选 | 约束 | 服务对象 | 妥协点（必须显式说明） |
|---|---|---|---|
| 方案 A（要辣组） | 不排除该维度、计入聚合偏好 | 强度 ≥3 的成员 | 不要辣成员需接受含辣菜品，可去酱料/换单品（其硬约束被违反时公平性如实记 0 分） |
| 方案 B（不要辣组） | 该维度升级为**硬排除** | 强度 ≤1 的成员 | 要辣成员接受全单无辣，可自备辣酱 |

> 注意：若「不要辣」一方是以**硬约束**表达的（如过敏级忌口），按 5.1 优先级，
> 方案 A 对其公平性记 0 分并附原因——这不是 bug，而是把协商成本显式摊开给用户看。

### 5.4 公平性评分计算方式

`fairness_score(plan, aggregated)` 对每个成员输出 0–1 满足度：

```
若成员个人硬约束被方案违反（禁忌标签/成分出现在菜品里）→ 直接 0 分（附原因）

否则（口味接近度 = 1 − |方案强度 − 成员强度| / 5，方案强度：含该标签菜品记 3，否则 0）：
  表达过口味偏好：score = 0.5 × 口味接近度 + 0.3 × 偏好命中率 + 0.2 × 避免命中率
  未表达口味偏好：score = 0.6 × 偏好命中率 + 0.4 × 避免命中率
  （偏好命中率 = prefer_tags 命中数/总数，无偏好记 0.5；
    避免命中率 = 1 − avoid_tags 命中数/总数，无避免记 1.0）
```

**整体公平性 = 全体成员最低分（木桶效应）**：最不满意的成员决定方案公平性上限。
展示时逐成员列明（如「小李 0.80｜小张 0.00（硬约束被违反：['spicy']）」），
让「谁被牺牲了」一目了然。
