# 麦麦拼单大脑（mcd-meal-brain）

> 面向多人场景的麦当劳智能点餐决策引擎 —— 一个把「一群人吃什么、怎么点最划算」算成可执行方案的 Agent Skill。

**参赛作品**：麦当劳 MCP 程序员创意开发大赛 · 作品形态：Agent Skill
**依赖**：Python 3.10+（纯标准库） · 麦当劳 MCP 服务（35 个工具）

---

## 一、解决什么问题

单人点餐只需要回答「想吃什么」；**多人点餐要同时满足三层互相打架的约束**：

| 层级 | 内容 | 特性 |
|---|---|---|
| **硬约束** | 忌口、过敏、预算上限、人数 | 违反即方案作废 |
| **软偏好** | 口味、热量、想吃辣的、要凑赠品 | 违反只扣分 |
| **团队目标** | 总价 / 人均、送达时间、凑券凑满减 | 需要全局寻优 |

难点在于**它们会互相冲突**：想省钱要凑单，凑单可能超热量；想健康要少油炸，少油炸又用不上大额满减券。

本项目做的事：**在约束空间里做多目标寻优，并给出可解释的取舍**。

---

## 二、核心能力

- **自然语言 → 结构化约束**：识别忌口成分（「不吃牛」「牛肉过敏」「不碰安格斯」归一为同一黑名单）、预算形式（总额 / 人均）、减脂档位、四种典型画像。
- **硬约束一票否决**：先过滤解空间再优化，且每个被剔除的商品都能回答「为什么没有它」。
- **组合优化**：动态规划（无界背包 + 券组合 DP）+ 帕累托剪枝求最省钱；加权评分求最健康 / 最快。
- **券来源严格区分**：只用 `query-store-coupons`（门店真实可用）算价，绝不混用「账户可领券」。
- **官方核价**：每个方案都过 `calculate-price` 核价，偏差超 5% 以官方价为准。
- **写操作强确认**：下单、取消、领券、建地址、抽奖一律先展示、后确认，绝不擅自执行。
- **营养化输出**：热量 / 蛋白 / 脂肪 / 钠全部给数值，不给「较健康」这种空话。

## 三、快速开始

```bash
# 1. 环境（Python 3.10+ 即可，无第三方依赖）
python --version

# 2. 配置 MCP（把示例复制到本机配置，并填入自己的 Token）
cp mcp-config.example.json ~/.workbuddy/mcp.json
export MCD_MCP_TOKEN="<从 https://open.mcd.cn/mcp 获取>"

# 3. 本地跑优化引擎（纯离线，不联网）
python scripts/optimizer.py            # 输出 Top-3 方案
python scripts/optimizer.py --selftest # 断言自检

# 4. 核价联调（需在门店营业时段 07:00–22:00）
#    见 scripts/optimizer.py::verify_price(plan, store_code, token=...)
```

## 五、演示场景

### 5.1 场景设定

> **用户输入**：「我们 4 个人拼单，人均 40 以内，有人减脂，有人不吃牛肉，忌辣，帮我把券用上凑个满减」

四位参与者的画像（由 `parse_constraints()` 自动解析）：

| 参与者 | 画像 | 硬约束 | 关键目标 |
|---|---|---|---|
| 小李 | 减脂 | — | 单餐 ≤600 kcal、脂肪 ≤25 g、蛋白 ≥20 g |
| 小王 | 忌口 | **不吃牛肉、不吃辣** | — |
| 小张 | 要赠品 | — | 凑满减、拿优惠 |
| 小陈 | 预算控 | **人均 ≤¥40** | 性价比优先 |

### 5.2 硬约束过滤结果

从 15 个候选餐品中**淘汰 5 个**并给出理由：

- ❌ 巨无霸、培根安格斯厚牛堡 → 命中忌口成分 `beef`
- ❌ 麦辣鸡腿汉堡、麦辣鸡翅 → 命中排除标签 `spicy`
- ✅ 保留 10 项：板烧鸡腿堡、麦香鱼、双层吉士汉堡、中薯条、小杯玉米杯、苹果片、无糖可口可乐中杯、麦乐鸡5块、圆筒冰淇淋、鲜蔬蛋沙拉叠叠卷

### 5.3 输出方案（Top-3）

```
🍔 方案｜最省钱
├ 双层吉士汉堡 ×2   ¥39.00
├ 中薯条 ×2         ¥24.00
├ 券组合：9折券（C004）  −¥6.30
├ 原价：¥63.00 → 最终价：¥56.70
├ 人均：¥14.18（预算 ¥40 ✅）
└ 人均 359 kcal｜蛋白 15.5 g｜脂肪 17.0 g

🥗 方案｜最健康
├ 板烧鸡腿堡 + 麦香鱼 + 双层吉士汉堡 + 麦乐鸡5块 + 鲜蔬蛋沙拉叠叠卷
├ 券组合：麦乐鸡立减5元（C003）−¥5.00 + 9折券（C004）−¥9.15
├ 原价：¥91.50 → 最终价：¥77.35
├ 人均：¥19.34（预算 ✅）
└ 人均 406 kcal｜蛋白 22.2 g｜脂肪 19.5 g   ← 蛋白最高、达标项最全

⚡ 方案｜最快
├ 板烧鸡腿堡 + 麦香鱼 + 双层吉士汉堡 + 鲜蔬蛋沙拉叠叠卷
├ 原价：¥77.00 → 最终价：¥69.30｜人均 ¥17.32
└ 人均 353 kcal｜蛋白 19.2 g｜非油炸项占比高，出餐更快
```

> 以上结果可由 `python scripts/optimizer.py` **一键复现**。营养数据取自 `list-nutrition-foods` 的真实值（160 个餐品）；券为内置示例券，用于演示券组合 DP。

### 5.4 省钱对比数据

**基线**：4 人各点 1 份板烧鸡腿堡（¥21.50），不使用任何优惠 → **¥86.00**，人均 **¥21.50**

| 方案 | 原价 | 券优惠 | 最终价 | 人均 | 相比基线 | 降幅 |
|---|---|---|---|---|---|---|
| **最省钱** | ¥63.00 | −¥6.30 | **¥56.70** | **¥14.18** | **省 ¥29.30** | **↓34.1%** |
| 最快 | ¥77.00 | −¥7.70 | ¥69.30 | ¥17.32 | 省 ¥16.70 | ↓19.4% |
| 最健康 | ¥91.50 | −¥14.15 | ¥77.35 | ¥19.34 | 省 ¥8.65 | ↓10.1% |

**关键结论**

1. **最省钱方案比朴素点法省 34.1%**（人均从 ¥21.50 → ¥14.18），且同时满足「4 人份 + 热量下限 + 不含牛肉/辣」。
2. **券的叠加能力被充分利用**：最健康方案同时命中「商品限定券 + 折扣券」，优惠额 ¥14.15 是三个方案中最高的（券按 `exclusiveGroup` 互斥、按 `minSpend` 校验门槛、按 `appliesToProductCodes` 校验适用范围，避免把「麦乐鸡券」用在没有麦乐鸡的订单上）。
3. **健康与便宜可以兼得，但有代价**：最健康方案人均蛋白 22.2 g（比最省钱高 43%），代价是人均多花 ¥5.16。
4. **预算约束全程有效**：三个方案人均均落在 ¥40 预算内，且输出中显式标注了达标情况。

## 六、技术方案

| 模块 | 实现 |
|---|---|
| 约束解析 | 正则 + 关键词表；成分同义词归一（牛/猪/鸡/鱼/辣/油炸/奶/花生…） |
| 硬约束过滤 | 一票否决 + 原因记录，先压解空间再优化 |
| 最省钱求解 | **动态规划**：无界背包（状态 = 份数 × 热量桶）最小化成本；券组合另一层 DP（分组互斥 / 门槛 / 商品范围 / 最多叠加 2 张） |
| 多目标收敛 | **帕累托剪枝**（成本↓ + 热量接近目标）后按加权评分排序 |
| 加权评分 | `cheap / healthy / speed / pref` 四维，权重由画像决定 |
| 核价校验 | 极简 MCP Streamable HTTP 客户端；**分 → 元**换算；偏差 >5% 以官方为准 |
| 错误处理 | 识别「业务错误不置 `isError`」的服务端行为，读 `structuredContent.success/code` |

**内建质量保障**：`--selftest` 覆盖 6 组断言，含 4 个已修 bug 的回归用例
（油炸误标、折扣券语义、浮点截断、券跨商品误用）与业务错误识别。

## 七、合规与边界

- 本项目**不是**麦当劳官方产品，与麦当劳公司无隶属或背书关系。
- **不含任何真实凭证**：示例配置仅含 `${MCD_MCP_TOKEN}` 占位符。
- **不采集用户数据**，偏好信息仅在当次会话内存中参与计算。
- **写操作一律需用户确认**后才执行；不伪造「下单成功」。
- 营养与价格数据仅供参考，**不构成医疗、营养或财务建议**；最终以官方渠道结算为准。

详见 [`CONTEST_DECLARATION.md`](./CONTEST_DECLARATION.md)。
